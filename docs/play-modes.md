# 隨機派對模式

派對不必先挑遊戲：選擇時間盒，或抽 8 款不同遊戲一路決戰。系統會記住這次抽出的清單，所有裝置都能看到目前進度。

| 模式 | 規則 | 抽選結果 |
|---|---|---|
| 3分鐘快閃 | 總時長上限 3 分鐘 | 1–2 款最短的遊戲（例如跟著做 + 敲木頭） |
| 5分鐘正常 | 總時長上限 5 分鐘 | 通常 2 款接力 |
| 10分鐘最久 | 總時長上限 10 分鐘 | 2–4 款，連較長的遊戲也有機會塞進來 |
| **決戰模式** | **玩完 8 款後才公布總排名** | **隨機抽 8 款不同、符合人數的遊戲；各局原始分數直接相加** |

決戰模式至少需要 **4 位玩家**，才能抽出 8 款不同且符合人數限制的遊戲。若人數不足，會提示補足玩家，不會用不適合人數的遊戲湊數。

## 使用者流程

1. **首頁／建立房間 → 隨機派對模式**（`/random`，也可從 `/create`、大廳或結算畫面開啟）。
2. 選擇時間模式或決戰模式、預計人數，查看隨機清單；可以重新抽選。每款遊戲都附上建議設定。
3. 開始派對後，房間載入清單第一款的大廳；房主仍可調整遊戲秒數／回合數。
4. 時間模式每款結束後會在結算畫面停留 20 秒，再前往下一款。決戰模式也會逐款接力，但中途只顯示進度，不顯示單局名次或排行榜。
5. 決戰模式第 8 款結束後，系統加總各局分數並公布總排名。完成後可再抽一場決戰；若回到大廳重玩最後一款，則會脫離已完成的決戰清單。

## 抽選邏輯（`src/lib/playlist.ts`，純函式）

1. **時間估算**：時間模式以遊戲 `estimatedDuration` 的最快端為錨點，依設定要求的份量（回合數 × 秒數）縮放。
2. **建議設定**：時間模式嘗試快速節奏、較少回合與最短合法秒數，找出塞得進預算的建議組合；決戰模式一律使用快速節奏建議。這些都是建議值，大廳仍可修改。
3. **時間模式裝箱**：只從單款估算能塞進上限的遊戲中挑；同一份清單不重複同一款，並優先挑仍有空間接下一款的遊戲。
4. **決戰抽選**：從可容納目前人數的遊戲中隨機抽 8 款，同一場不重複。若合格遊戲不足 8 款，就回傳不完整清單並提示玩家人數不足，不會開始不完整的決戰。
5. **盡量不重複**：`lib/playHistory.ts` 會用 localStorage 記錄最近 6 小時玩過的遊戲，抽選優先挑較新鮮的遊戲；若不足以完成清單，才會使用近期玩過的遊戲。跨場次可重複，但單一清單不重複。
6. **保底**：時間預算短到沒有任何遊戲能塞入時，仍會提供最快的一款；決戰模式則不會放寬玩家人數限制。

## 房間狀態

```ts
sessionPlan?: {
  mode: "flash" | "standard" | "marathon" | "battle";
  budgetMinutes: number | null; // 決戰模式為 null
  entries: { gameId; minutes; settings; repeated? }[]; // entries[0] = 目前這款
  played: string[];                         // 已完成的遊戲（依序）
  totalScores?: Record<string, number>;      // 決戰模式的跨局累積分數
  startedAt: number;
  completedAt?: number;
}
```

- `src/lib/gameSession.ts`
  - `startRoomSession(room, plan)`：載入第一款遊戲及建議設定；決戰清單必須恰為 8 款不同遊戲。
  - `advanceRoomSession(room, now)`：從 RESULTS 將目前遊戲移入 `played` 並升上下一款；決戰模式同時累加本局分數，且不能跳過尚未完成的遊戲。第 8 款完成後保留在 RESULTS，寫入 `completedAt` 與完整總分。
  - `leaveRoomSession(room, gameId)`：房主手動換成清單以外的遊戲時離開隨機模式。
- `src/app/room/[roomCode]/results/ResultsClient.tsx`：決戰中途隱藏單局排行榜；完成 8 款後顯示累積排名與可分享的決戰戰報。
- `database.rules.json` 不需修改：`sessionPlan` 沿用房主寫入房間狀態的授權。
